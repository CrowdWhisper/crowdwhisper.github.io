**The idea.** People often use "coin" and "token" as if they mean the same thing. They do not. A coin is the native asset of its own blockchain. A token is created by a smart contract on a chain that already exists <a class="cite" href="#src-1">[1]</a><a class="cite" href="#src-2">[2]</a>. That difference shows up in how an asset is issued, what it can do, and which currency you pay to move it. Sending a token on Ethereum still costs ether (ETH) for the network fee, even if you never meant to hold ETH <a class="cite" href="#src-3">[3]</a>.

{% capture t %}**A short history.** The distinction existed once early alternative coins launched their own chains, but it became central after Ethereum added programmable smart contracts. In November 2015 Ethereum developers published the ERC-20 standard, a common interface for fungible tokens — units that are interchangeable with one another. That let a project launch an asset without building a new blockchain from scratch [4][5].

Most assets in circulation today are tokens, not native coins. CoinGecko's public global API listed 21,248 actively tracked cryptocurrencies at 17:56 UTC on 25 November 2026 [6]. That curated list is only a slice of what exists on-chain. CoinGecko's own documentation, updated 13 November 2026, says its API tracks 50 million+ tokens [7]. At Solana's Breakpoint conference (15–17 November 2026), CoinGecko co-founder Bobby Ong said the platform tracks more than 50 million tokens across 220 blockchains [8].

Some projects begin as tokens and later migrate. BNB launched as an ERC-20 token on Ethereum in 2017. In April 2019 it moved to Binance's own chain, now called BNB Chain, and became the native coin used to pay fees on that network. Official BNB Chain documentation records the 2017 ERC-20 origin and dates the mainnet launch to 18 April 2019. Contemporaneous coverage said the holder swap from ERC-20 to the native BEP-2 coin was due to begin on 23 April 2019 [9][10][11].{% endcapture %}

{% capture t %}**How it works.** A coin is written into the rules of its blockchain. Bitcoin exists only on the Bitcoin network. Ether exists only on Ethereum. Solana's SOL exists only on Solana. New units are created according to the protocol's consensus rules — proof-of-work mining or proof-of-stake validation. Fees for every transaction on that chain are paid in the native coin [1][3].

A token is a balance recorded inside a smart contract. On Ethereum the most common standard for interchangeable tokens is ERC-20. The contract keeps a list of addresses and how many tokens each holds. When someone sends tokens, the contract updates those balances [4][5]. The host chain's validators still process the transaction, so the sender must also hold and spend the host chain's native coin to cover the fee. Ethereum's documentation is direct: gas fees have to be paid in ether [3]. Sending USDC on Ethereum therefore requires ETH for the fee [3][12].

Creating a coin means launching and securing an entire blockchain. Creating a token means deploying a contract that follows a known standard. That difference in effort is why a single chain can host a very large number of tokens while having only one native coin [1][2].{% endcapture %}

{% capture t %}**Use cases.** Coins mainly serve as the medium of exchange and a store of value for their own network. Bitcoin is widely used as a digital store of value. ETH pays for computation on Ethereum and secures the chain through staking. SOL does the same on Solana [1][2].

Tokens expand the set of possible functions. Stablecoins such as USDC represent a claim on off-chain reserves and are used for payments and trading [12]. Governance tokens such as UNI let holders vote on protocol parameters. Utility tokens grant access to services. Non-fungible tokens (NFTs) represent unique items under a different standard (ERC-721 on Ethereum) [13]. Real-world asset tokens aim to represent claims on bonds, gold or other off-chain property [1][2].

Because tokens inherit the security and tooling of their host chain, projects can focus on the application rather than the base-layer infrastructure.{% endcapture %}

{% capture t %}**Trade-offs.**

**Coins.** Pros: an independent security model; no reliance on another chain's governance or downtime; fees paid in the asset itself. Cons: expensive and slow to launch; each new chain must attract validators and users; limited to one native asset per chain.

**Tokens.** Pros: faster and cheaper to issue; inherit host-chain security and tooling; easy interoperability with existing wallets and exchanges. Cons: depend on the host chain for uptime and fee pricing; smart-contract bugs can freeze or drain funds; many tokens have no independent utility and die quickly [1][2].

The practical consequence for users is simple: always check which network an asset lives on before sending. Sending a token to an address that expects the native coin, or choosing the wrong network in a withdrawal, can result in permanent loss. Ethereum's documentation notes that ERC-20 tokens sent to a contract that cannot handle them can be lost for good [4].

| Feature | Native coin | Token |
|---|---|---|
| Blockchain | Own independent chain | Existing host chain |
| Creation | Protocol rules / consensus | Smart-contract deployment |
| Fee payment | In the coin itself | In the host chain's native coin |
| Security | Own validators or miners | Inherits host-chain security |
| Typical uses | Network fees, store of value | Stablecoins, governance, utility |
| Examples | BTC, ETH, SOL, BNB (after 2019) | USDC, UNI, SHIB, LINK |
| Launch effort | High (a new chain) | Low (a standard contract) |

Sources for the table: CoinGecko Learn, Kraken Learn and ethereum.org [1][2][3][4].{% endcapture %}

{% capture t %}**Looking forward.** Layer-2 networks and cross-chain bridges continue to blur the practical line. Assets can be bridged so that a token on one chain represents a claim on a coin or token elsewhere. Projects still occasionally migrate from token to native coin when they want independent fee markets or consensus rules. Regulatory treatment increasingly depends on how an asset is marketed and used rather than the technical label "coin" or "token."

Users and developers will keep needing to know which chain an asset lives on, because that single fact determines the fee currency, the security assumptions, and the recovery options if something goes wrong. What comes next is not a forecast, and nothing in this article is financial advice.{% endcapture %}
